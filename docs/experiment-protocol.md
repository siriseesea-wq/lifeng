# 砺锋 v2 — 阶段一实验协议

**T7 产物** · 2026-10-10 · 状态：AI 起草，**待用户确认被试与合规部分**

> 本协议冻结**测量方法**，目的是防止事后解释数据。
> 协议一旦开始执行（T8），**不得中途修改判定规则**。

---

## 1. 要验证的命题

> **「人工标注骨架 + LLM 措辞」能否稳定产出不泄答案、且学生确实推进的提示？**

具体化为两个可观测问题：

1. **有效吗** —— 接受分层提示的学生，比无提示时更容易越过卡点吗？
2. **是真引导吗** —— 越过卡点时，依赖的是第几层提示？

第 2 问同样重要。若学生几乎都在**第 3 层**（具体动作）才突破，
那提示已接近"直接告知"，与"苏格拉底引导"名不副实。

---

## 2. 被试

| 项 | 要求 |
|---|---|
| 人数 | **≥3 名**（硬性下限，不足则 T8 不得执行）；**目标 4 名或 6 名** |
| 对象 | 化学竞赛生，已学过有机化学基础，能对机理做推理 |
| 年龄 | 记录年龄；不满 14 周岁需监护人书面同意（见 §8） |
| 排除 | 按**题目级**筛除，不做全局排除（见 §2.2） |

### 2.1 为什么目标人数必须是偶数

§3.1 的 A/B 顺序轮换要求两臂人数相等才能完全平衡：

| 人数 | 基线优先 : 实验优先 | 平衡 |
|---|---|---|
| 3 | 2 : 1 | ❌ 失衡 |
| **4** | **2 : 2** | ✅ **完全平衡（最小可行）** |
| 5 | 3 : 2 | ❌ 失衡 |
| **6** | **3 : 3** | ✅ 完全平衡 |

因此 **4 或 6 才是正确目标**。原稿写"目标 4~5 名"是错的 ——
5 与 3 一样会引入顺序效应失衡。人数无法凑成偶数时，
按 §3.3 记为局限，不得隐去。

### 2.2 为什么改为按题筛除，而不做全局排除

原稿要求"未系统做过频哪醇重排等经典机理题"。这条**几乎筛不出人**：

- 够强到能对机理做推理的学生，多半已经刷过经典机理题
- 没刷过的学生，往往还没建立起推理基础

更麻烦的是，这条标准与"题库是经典机理题"直接冲突。

**改为题目级筛选**：T6 完成 20 题后，让候选人对每道题自评熟悉度
（没做过 / 见过但不记得 / 做过）。**该学生自评"做过"的题，不进入他的题目集**，
从剩余题里补齐。这样既不损失被试，又不会采到被记忆污染的数据。

## 3. 实验设计

### 3.1 被试内设计 + 题目分半

n=3~5 太小，**组间设计没有统计效力**。因此采用被试内设计：每名学生都经历两种条件。

- 20 道题按难度与机理类型**配对**分成 A、B 两组各 10 题
- 每名学生完成全部 20 题
- **同一道题不会在同一名学生身上被两种条件各用一次** —— 避免学习污染

| 学生 | A 组（10 题） | B 组（10 题） |
|---|---|---|
| S1, S3, S5 | 基线（无提示） | 实验（可请求提示） |
| S2, S4 | 实验（可请求提示） | 基线（无提示） |

**轮换的作用**：抵消 A/B 两组本身的难度差异。

### 3.2 分两次会话

每人分 **2 次**完成，间隔 **≥1 天**，每次 10 题。
单次连续做 20 道机理题会产生严重疲劳，污染后半段数据。

### 3.3 顺序效应（已知局限）

先做的那一组会因熟悉题型而占优。轮换只能**部分**抵消，
n 小时尤其如此。此局限必须在 T9 报告中写明，不得隐去。

---

## 4. 单题流程与时限

```
学生读题
  ↓
提交尝试 ──────────────┐
  ↓                     │ 反复进行，直到：
[实验组] 卡住 → 请求提示 │  (a) 学生完成
  ↓                     │  (b) 学生声明放弃
[基线组] 卡住 → 只能继续 │  (c) 达到单题时限
  ↓                     │
记录本次尝试 ────────────┘
```

| 项 | 设定 |
|---|---|
| 单题时限 | **15 分钟**（含提示等待时间）；实验者可依题目难度微调并记录 |
| 基线组可用的帮助 | 仅限系统界面本身；**禁止**查资料、问人、用其他 AI |
| 实验组提示上限 | 第 3 层（第 4 层给答案，**仅在学生明确要求"我想看答案"时**使用，且该次不计入推进率） |
| 每层提示后 | 学生必须再提交一次尝试，才能请求下一层 |

> **第 4 层不计入推进率** —— 它给出答案，用它衡量"引导是否有效"毫无意义。
> 单独统计"有多少题最终走到第 4 层"，作为难度信号。

## 5. 卡点判定规则（本协议最核心的部分）

判定质量决定整个实验的成败。n=20 时由**实验者人工判定**
（不构建自动判定器，理由见计划 §3）。

### 5.1 判定对象

每次学生提交后，实验者对照该题骨架的 `pitfalls` 列表，判定两件事：

1. **当前处于哪个卡点** → 回填 `attempts.pitfall_index`（从 0 起）
2. **是否越过了上一个卡点** → 回填 `attempts.progressed`（0/1）

### 5.2 「越过」的唯一判据

> 学生的**下一次提交**中，出现了该卡点 `next_step` 所描述的动作。

**只看 `next_step`，不看学生是否得出了正确答案。**
学生可能越过了卡点但在后续步骤又走错 —— 这仍算越过。

### 5.3 判定示例（用 p001 校准）

卡点 1（`next_step` = "把注意力拉回只有一个羟基被质子化并脱水，
让学生确认第二个羟基此时以什么形式存在"）：

| 学生下一次提交 | 判定 | 理由 |
|---|---|---|
| "是不是只有一个羟基会脱水，另一个还留着？" | ✅ 越过 | 出现了"第二个羟基留着"这一动作 |
| "两个都脱水生成双键" | ❌ 未越过 | 重复了原错误 |
| "我猜是频哪酮" | ❌ 未判定 | 猜中产物不等于越过卡点；且此时实验者应确认是否泄漏 |

### 5.4 判定可靠性检查（必做）

- **事前校准**：正式执行前，用 p001 的模拟记录试判一遍，确保标准一致
- **事后自查**：隔天重判 **≥20%** 的记录，计算自一致率
  - 一致率 **<80%** → 判定标准不可靠，需重新校准，**已判数据全部重判**

这一步不能省。主观判定若不自查，数据只是实验者的印象。

## 6. 指标

### 6.1 主指标

| 编号 | 指标 | 计算 |
|---|---|---|
| **M1** | 卡点突破率 | 越过的卡点数 ÷ 遇到的卡点数，分别对 baseline 与 hint 两种 mode 计算 |

### 6.2 关键辅助指标

| 编号 | 指标 | 为何关键 |
|---|---|---|
| **M2** | **突破所依赖的提示层级分布** | 区分"真引导"与"变相告知"。若突破集中在第 3 层，说明引导名不副实 |
| M3 | 泄答案率 | 第 1~3 层出现答案关键量的比例，**必须为 0** |
| M4 | 骨架未命中率 | 学生卡在骨架未覆盖的地方 → 飞轮的启动信号 |
| M5 | 记忆型题误入引导流程 | **必须为 0** |
| M6 | 走到第 4 层的题目比例 | 难度信号，不计入 M1 |

### 6.3 判定规则（照抄 Design Spec §5.4，不得放宽）

| 结果 | 判定 |
|---|---|
| **M1 实验 > 基线** 且 **M3 = 0** 且 **M5 = 0** | ✅ 方向成立，进入阶段二 |
| M1 实验 ≤ 基线 | ❌ **方向重估**，不进入平台建设 |
| M3 > 0 或 M5 > 0 | ⚠️ 实现缺陷，先修复再判 |

**M2 特别说明**：M2 不设硬性阈值，但若第 3 层突破占多数，
即便 M1 通过，也应在报告中明确指出**分层设计需要重新设计层 3**。

> **禁止事项**：不得通过调整阈值、扩大题量、修改判定规则、
> 或"再跑一批看看"来挽救不利结论。这是本协议存在的主要目的。

## 7. 记录与回填

### 7.1 自动记录

界面自动写入 `store.db`：

- `sessions.mode` —— `baseline` / `hint`（实验者按 §3.1 在侧栏选择）
- `attempts.level_requested` —— 请求的提示层级（基线恒为 0）
- `attempts.hint_text` —— 系统给出的提示
- `attempts.leaked` —— 是否走了掩码兜底

### 7.2 人工回填

实验者事后回填两列（判定规则见 §5）：

```sql
-- 该次尝试处于哪个卡点（从 0 起）
UPDATE attempts SET pitfall_index = ? WHERE id = ?;

-- 是否越过了上一个卡点
UPDATE attempts SET progressed = ? WHERE id = ?;
```

> **执行提示**：20 题 × 4 人 × 平均 4 次尝试 ≈ **300 条回填**。
> 手工敲 SQL 既慢又易错，建议 T8 前先做一个最小回填 CLI。
> 该 CLI 属 T9 前置，本协议不展开。

### 7.3 必须备份

执行前、执行中每日、执行后，各备份一次 `store.db`。
原始记录一旦丢失，整个实验作废。

## 8. 伦理与数据安全

| 项 | 要求 |
|---|---|
| 年龄确认 | 记录每名被试年龄；**不满 14 周岁**个人信息在《个人信息保护法》中属敏感个人信息，须取得监护人**书面**同意 |
| 告知 | 向学生与监护人说明：数据用途、保存期限、删除方式、可随时退出 |
| 数据范围 | **只采集**答题文本与提示记录。**不采集**身份信息、学校、成绩、情绪/心理数据 |
| 存储 | 实验期仅存本地 `store.db`；不接入任何第三方分析；不入 git（已在 `.gitignore`） |
| 删除 | 实验结束后 **30 天内**按约定删除，或应要求立即删除 |
| 退出权 | 学生可随时退出，已收集数据随之删除 |

> 本实验**不含任何心理/情绪模块** —— 这是 Design Spec 把心理层移出 v1 的直接收益：
> 合规面从"处理未成年人敏感情绪数据"降到"处理答题文本"。

## 10. 已知局限（必须写入 T9 报告）

1. **样本量小**（n=3~5），只能做**方向判定**，不能估计效应量，**不报 p 值**
2. **顺序效应**：轮换只能部分抵消（见 §3.3）
3. **实验者即开发者**：判定存在主观偏差，靠 §5.4 的自查部分缓解
4. **卡点判定是人工的**：可靠性上限受实验者判断力限制
5. **提示质量受 LLM 波动影响**：同一层提示在不同题目上质量不一致
6. **泄漏检测是字符串黑名单**：拦不住改述型泄漏，靠人工复核兜底
7. **单科目单题型**：仅有机推理题，结论不可外推到物化/结构/记忆型内容
