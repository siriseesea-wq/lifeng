# 砺锋 v2 — 化学竞赛苏格拉底引导陪练

**Design Spec** · 2026-10-10 · 状态：待用户复核

**取代关系**：本文档取代此前的《砺锋 LiFeng — 技术方向文档》。
该文档的技术主张经实证检验后大部分不成立（见 §8），不再作为设计依据。

---

## 1. 背景

原方向文档提出"站在开源项目肩膀上"的竞赛 AI 训练系统，包含七 Agent、
IRT 掌握度、依据锚定引擎等。经逐步实证，发现四类问题：

### 1.1 引用不实

| 引用 | 文档说法 | 实测 |
|---|---|---|
| DeepTutor | 多 Agent / 三层记忆 / 流式 / RAG | ✅ `HKUDS/DeepTutor` ★41,078，Apache-2.0，活跃 |
| 活书 huoshu | IRT 2PL / SM-2 / 知识图谱 | ⚠️ PyPI `learning-agent` v1.0.1，作者匿名；**19 个依赖中无任何 IRT 库** |
| OI.SKILL | 苏格拉底引导 / 错误诊断 / 跨 Session 记忆 | ⚠️ `FlashingChen/oi.skill` ★15、fork 1、活跃两周后停更 |
| P1-30B-A3B | 物理竞赛推理 / RL 配方 | ⚠️ 实为模型权重（HuggingFace），非可继承架构 |
| **EGPE** | 核心依据锚定原则 | ❌ **多轮检索零命中** |
| **Shadow-Forced** | 强制每步调用工具 | ❌ **多轮检索零命中** |

后两项被文档当作核心卖点，却无任何出处 —— 该文档违反了它自己写下的
"没有文献支撑的规则禁止写入"。

### 1.2 统计上不成立

IRT 2PL 的项目参数须从**多人作答矩阵**估计。单用户场景下参数不可识别；
多用户场景在**启动期**（零作答数据）同样不可识别。原文档把 IRT 当起点，
实际它只能是终点。

### 1.3 内部矛盾

- 七 Agent 串行链 + "每步调用验证" + "秒级反馈"三者不可兼得
- ~~"数据本地优先、默认不上传云端" 与 "跨用户沉淀错误模式库" 不可兼得~~
  —— **此条判断有误，已撤销**：本地多学生即可兼得（见 C4 修正）

### 1.4 缺失关键定义

无验收标准、无科目优先级、无成功判据。唯一抄不到的资产（错误模式库）
只有一句话描述。

## 2. 目标与非目标

### 2.1 目标

为化学竞赛生提供**苏格拉底式分层引导**：学生卡住时，按四层递进给提示，
前三层不泄答案，并在每次交互后记录是否推进。

### 2.2 非目标（v1 明确不做）

| 非目标 | 理由 |
|---|---|
| IRT / 掌握度建模 | 启动期无数据，且对"引导"楔子无用 |
| 七 Agent 编排 | 与延迟要求矛盾；v1 只需两个真实组件 |
| 心理 / 情绪模块 | 合规风险最高，价值最难证明，与楔子无关 |
| 计划 / 计时 / 复习模块 | 与引导楔子无关，Anki 类工具已占位 |
| 知识图谱 / 三层记忆 | 骨架本身即结构，v1 不需要 |
| 教练端 / 多端同步 / 协作 | 本地工具，不需要平台功能 |
| 数学 / 物理 / 信息学竞赛 | v1 只做化学，多科目并行等于都做不完 |
| 本地优先部署 | ~~与标注飞轮不相容~~ **已撤销** —— 本地多学生下飞轮照常工作（见 ADR-001 修正） |
| 云部署 / 多租户 / 账号体系 | **延后**（非永不）—— 学生就在身边，共用一台机器即可；见 ADR-001 的迁移触发条件 |
| 模型训练 / 微调 | 用现成 LLM，成本与周期不可控 |

### 2.3 v1 科目范围边界

化学竞赛内部有五个子领域，**v1 只做有机化学的推理型内容**：

| 子领域 | v1 处置 |
|---|---|
| **有机化学（机理 / 合成推断）** | ✅ v1 范围 |
| 物化（计算建模） | 延后 |
| 结构（光谱推断） | 延后 |
| 无机 / 元素化学 | 延后（且以记忆型为主，见 C2） |
| 分析化学 | 延后 |

**依据**：楔子是苏格拉底引导，而引导只对推理有效（见 C2）。
有机机理是化学中推理密度最高、错误模式最程式化的部分，
最适合验证"引导是否真的有效"这个唯一命题。

> 此项为收敛推论，**需用户在复核时确认**。若用户主张改为物化或结构，
> §4.3 C2 的推理型筛选逻辑不变，但标注成本与错误模式会完全不同。

## 3. 已确认决策

| # | 决策 | 选择 |
|---|---|---|
| 1 | 使用范围 | **本地多学生工具**（我 + 我带的几个学生，跑在本机） |
| 2 | 科目 | **化学竞赛** |
| 3 | v1 楔子 | **苏格拉底分层引导陪练** |
| 4 | 提示骨架来源 | **人工标注骨架 + LLM 措辞** |
| 5 | 题目入口 | **开放输入 + 标注飞轮** |

> **决策 1 修正记录（2026-10-10）**：原为「多学生产品（非个人工具）」，
> 用户澄清为**本地自用** —— 即"我和我带的几个学生用，不部署服务器"。
> 这不是单人工具：学生数仍 ≥3，实验设计与飞轮均成立；
> 变化的是**不再是商业产品**，因而服务端架构、市场与付费风险全部不适用。

## 4. 系统设计

### 4.1 领域模型（三个实体）

```
Problem   题干 · 答案 · 领域标签(有机/物化/结构/无机/分析)
          · 类型(记忆型|推理型) · 被问次数
Skeleton  关键洞察 ×1 + 卡点 ×3~4
          每个卡点 = { 触发条件, 指向的下一步, 常见错误走向 }
          答案关键量清单（供泄答案校验使用）
Session   学生的每次尝试 · 系统给出的提示层级 · 是否推进
```

标注队列不是新机制，就是一条查询：

```sql
SELECT * FROM Problem WHERE skeleton IS NULL ORDER BY 被问次数 DESC
```

### 4.2 核心循环

```
学生提交【题目 + 自己的尝试 / 卡住的点】
  │
  ├─ 骨架匹配 ──┬─ 命中 → 精标模式
  │             └─ 未命中 → 通用模式，并自动入标注队列
  │
  ├─ 卡点定位：将学生尝试映射到骨架中的某个卡点
  │
  ├─ 提示阶梯：① 问方向 → ② 具体提示 → ③ 更具体 → ④ 答案 + 复盘
  │
  └─ 记录：停在第几层？下一层后是否推进？
```

### 4.3 四条硬约束

#### C1 · 不泄答案靠校验器，不靠 prompt

骨架显式标注"答案关键量"。第 1~3 层输出生成后过黑名单校验，
命中则重生成。**这是方案 4（人工骨架）唯一真正可控之处**，
也是它相对"纯 LLM 生成"的差异点所在。

#### C2 · 记忆型题目不进引导流程

题目建库时打 `记忆型 / 推理型` 标签。记忆型直接走卡片检索，
不进入提示阶梯。

**依据**：苏格拉底引导只能作用于推理，不能作用于记忆。
元素化学、人名反应、试剂特性无法被"问"出来。化学竞赛中记忆型内容
占比很高，不承认这条边界，系统会在该题型上体验崩塌。

#### C3 · 核心指标是推进率，不是"引导得像不像"

定义：**在同一卡点上，学生收到第 N 层提示后，下一次提交越过该卡点的比例。**

这是唯一能证明引导有效、也是唯一能给标注队列排优先级的信号。

#### C4 · 按未成年人标准处理数据

竞赛生横跨初中到高中。不满 14 周岁的个人信息在《个人信息保护法》中
属敏感个人信息，需监护人单独同意。

最低要求：数据最小化采集 · 明确告知 · 监护人同意路径 · 不出售数据。

> **修正记录（2026-10-10）**：原文写"本约束与决策 5 共同决定了**数据必须服务端存储**，
> 原文档的'本地优先'在此被推翻"。**该结论是错的，已撤销。**
>
> 我当时的推理是"跨用户沉淀错误模式库要求数据离开本地"，
> 但那是把"多用户"误当成了"必须上云"。**本地多学生**（学生共用一台机器）
> 同样能跨学生累积数据，飞轮照常工作。
>
> 修正后：**数据留在本机**。合规面因此更窄 ——
> 不存在第三方数据处理者、不存在传输环节、不存在云端留存。
> 但未成年人同意的要求不变。

## 5. 阶段一验证

### 5.1 唯一要验证的命题

> **"人工骨架 + LLM 措辞"能否稳定产出不泄答案、且学生确实推进的提示？**

### 5.2 最小实验

| 项 | 设定 |
|---|---|
| 题量 | 手标 20 道**有机**推理题 |
| 学生 | 3~5 名化学竞赛生 |
| 对照 | **必须测基线**：同一批学生在无系统辅助下的推进率 |
| 周期 | 2 周 |

### 5.3 观测指标

| 指标 | 判定 |
|---|---|
| 第 1~3 层后推进率 | 需显著高于基线；阈值待基线测出后确定 |
| 泄答案率 | 第 1~3 层出现答案关键量 = **0** |
| 记忆型题误入引导流程 | **0** |
| 骨架未命中率 | 记录，作为飞轮启动信号 |

> **不预设绝对阈值。** 没有基线的"60% 推进率"无法解释。
> 先测基线，再定合格线。

### 5.4 停止条件

若 20 题实验显示推进率**不高于**无系统基线，则整个方向重估 ——
不进入平台建设。

## 6. 风险

| # | 风险 | 严重度 | 对策 |
|---|---|---|---|
| R1 | ~~化学竞赛是小市场 / 付费意愿~~ **已撤销** —— 本地工具，不面向市场，无付费方 |
| R2 | **归因困难**：学生进步可能来自你本人的教学，而非工具 | 高 | 这是本地场景的核心混淆。协议设基线条件正是为了分离"工具"与"无工具"；但你同时是他们的老师，仍无法完全排除 |
| R3 | **标注负担全落在你一人身上** | 高 | 飞轮只能告诉你"该标哪道"，标注本身不可外包。见 §9 新开放问题 4 |
| R3 | 标注成本随题库线性增长 | 中 | 飞轮按"被问次数"排序，优先标真实高频题 |
| R4 | 骨架未命中时降级为纯 LLM，体验分裂 | 中 | 明确告知用户当前模式；把降级当数据采集而非失败 |
| R5 | 题目去重/相似归并（同一题不同表述） | 中 | v1 可先人工合并，样本量小时够用 |
| R6 | 未成年人数据合规 | 高 | 见 C4；上线前需法律意见 |

## 7. ADR 信号

以下决策触及持久架构面，需登记 ADR：

| ADR | 决策 | 触及面 |
|---|---|---|
| ADR-001 | **本地优先，服务端延后**（见下方说明） | 持久化边界 / 迁移触发条件 |
| ADR-002 | 化学答案可验证性升为架构主轴 | 架构方向 / 能力边界 |
| ADR-003 | 记忆型 / 推理型题目分流 | 领域模型 / 行为契约 |

### ADR-001 详述：本地优先，服务端延后

**当前决议（2026-10-10）**：数据留本机，学生共用一台机器上的 `store.db`。

**为什么现在不上服务器**：学生就在身边，同机即可。上服务器会立刻引入账号、
传输、第三方数据处理与运维 —— 这些成本在"提示到底有没有用"被验证之前，
收益为零。

**迁移触发条件**（满足任一即应重新评估，而不是含糊地"以后再说"）：

| # | 触发条件 | 为什么它会逼出服务器 |
|---|---|---|
| 1 | 学生**不再同处一地**（远程 / 异地） | 本机无法被远程访问，或需暴露内网 |

> **触发条件 1 的灰色地带**：「同处一地」**不等于「同一台机器」**。
> 界面是 Streamlit，本身就在 HTTP 上提供服务 —— 学生用局域网内的
> 自己的设备访问你的机器即可，**不需要服务器**。
> 所以条件 1 的真正含义是「**不在同一网络可达范围内**」，
> 而不是「不在同一台机器上」。
>
> 并发方面已实测：本地多学生与连接频繁开关的模式下未出现写锁冲突
> （见 `lifeng/store.py` 模块文档的「并发」一节），因此局域网多设备访问
> 在存储层没有额外门槛。
| 2 | 学生数超过一台机器可支撑的**并发与隔离** | 多人并发写同一库，且要互相看不到 |
| 3 | 学生需要**跨设备续做**（家 / 校接着做） | 状态必须离开单一机器 |
| 4 | 不希望**跨学生数据**依赖某一台机器的存活 | 单点故障 |

**为不让迁移变贵，现在就立的纪律**：

> **只有 `store.py` 可以 import `sqlite3`；其余模块只使用 `StoreError`。**

由 `tests/test_storage_boundary.py` 自动强制。将来换后端时，
改动面被限制在一个文件内，而不是扩散到界面与业务逻辑。

**此纪律已修正的一处违约**：`app.py` 曾直接 `import sqlite3` 并捕获
`sqlite3.Error` —— 界面层知道了存储后端。已改为由 `Store` 把后端异常翻译成
`StorageError`（`StoreError` 的子类），调用方只需 catch `StoreError`。

**优先级决议（2026-10-10）**：用户明确 —— 服务端 / 远程访问功能
**排在最后再加**。

因此本项的状态是：

| 维度 | 结论 |
|---|---|
| 现在要做吗 | **不做** —— 四个触发条件均未成立 |
| 优先级 | **最低，排在全部功能之后** |
| 何时重新评估 | 上表任一触发条件成立时 |
| 现在要做什么准备 | 只需守住上面那条纪律（后端关在 `store.py`），**不预建任何服务端代码** |

> 这两句决议并不冲突：触发条件回答「**何时必须做**」，
> 优先级决议回答「**现在该投多少**」。前者防止永远不做，
> 后者防止提前做。
>
> **不预建**是这里最要紧的一条 —— 没有触发条件成立时写服务端代码，
> 就是在为一个可能不存在的需求付出真实的维护成本。

## 9. 开放问题

1. 骨架中"答案关键量"的标注粒度如何定义？（过粗会漏检，过细会误杀）

   （本地多用户带来的新问题；候选人选：每人独立目录 / 界面按学生代号隔离 / 接受并告知）
